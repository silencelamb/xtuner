# L3 — checkpoint ecosystem: DCP round trip and HF export on the decoupled layout

```bash
PYTHONPATH=. torchrun --nproc-per-node 8 tests/model/run_decoupled_ep_fsdp_ckpt.py \
    --modes A:ep=1 C:ep=8,decouple=1 C4:ep=4,decouple=1 H41:ep=4,decouple=1,hsdp=4 \
    --cross-load C:A A:C C4:H41 --out l3/
```

Same tiny Qwen3-MoE / data / optimizer as L1. Per mode: `from_hf` → `save_hf` (step 0) → 5 steps → `save_dcp` → 5 steps → `save_hf` (step 10); then a fresh engine `load_dcp`s the step-5 checkpoint and trains steps 5–9.

| mode | config |
|---|---|
| A | ep=1, decouple=False, hsdp_sharding_size=None |
| C | ep=8, decouple=True, hsdp_sharding_size=None |
| C4 | ep=4, decouple=True, hsdp_sharding_size=None |
| H41 | ep=4, decouple=True, hsdp_sharding_size=4 |

Noise floor: two independent runs of the same `ep=1` configuration (mode A in `reports/L1.md` and in `reports/L2.md`) differ by up to `2.3e-05` (rel, first 10 steps) / `2.6e-05` (50 steps) — the training loop itself is not bit-deterministic run to run (NCCL reduction order, grouped GEMM). Differences at or below this level are noise.

## Float8 (tile-wise) on the decoupled layout

PR-3 gives routed experts their own fp8 padding chunk count (`efsdp`) and tile-wise reduce meshes with the `efsdp` rank stride, while dense fp8 linears keep `dp_shard`-based ones. Validated on the 3.4B medium model (`--fp8 --model-size medium --seq-len 4096`, 20 steps); the tiny model cannot be used because its fp8 grouped GEMM crashes on the legacy path too (see `reports/decisions.md` D11).

| pair | max rel loss diff (20 steps) | step-0 per-param grad-norm max rel diff: dense / expert |
|---|---|---|
| A vs B | 1.99e-04 | 4.16e-03 / 1.88e-02 |
| C vs B | 9.07e-04 | 3.49e-03 / 2.93e-04 |
| C4 vs B | 3.71e-04 | 6.74e-03 / 4.77e-03 |

fp8 training is noticeably less deterministic than bf16: repeating the *same* configuration twice (`A`/`A2`, `B`/`B2`, `C`/`C2`) gives

| pair | max rel loss diff (20 steps) |
|---|---|
| A vs A2 | 6.42e-04 |
| B vs B2 | 1.73e-04 |
| C vs C2 | 7.18e-04 |
| C vs A | 4.78e-04 |
| C2 vs A2 | 5.36e-04 |

so the decoupled-vs-legacy differences above are inside the fp8 run-to-run noise floor.

Step times with a warm `adaptive_gemm` JIT cache (second run, steps 5-19): A 203 ms, B 254 ms, C 264 ms / C2 260 ms — decoupled and legacy within 4% (the bf16 medium run in `reports/L1.md` had C 4.7% faster); the first fp8 run of a new shape pays the JIT compile (1906 ms/step average for B, 2026 ms for C4).

Per-rank memory (medium, fp8): A: dense params 105 MiB, peak allocated 9195 MiB; B: dense params 836 MiB, peak allocated 11861 MiB; C: dense params 105 MiB, peak allocated 8203 MiB; C4: dense params 105 MiB, peak allocated 8203 MiB.
