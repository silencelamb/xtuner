# L1 — single node, 8×H200: numerical equivalence of the decoupled layout

Environment: torch 2.9.1+cu128, transformers 5.14.1, 8×H200 (NGC 25.03 base image).

```bash
PYTHONPATH=. torchrun --nproc-per-node 8 tests/model/run_decoupled_ep_fsdp_numerics.py \
    --modes A:ep=1 B:ep=8 C:ep=8,decouple=1 --steps 50 --seq-len 2048 --out l1.json
python tests/model/summarize_decoupled_ep_fsdp_numerics.py l1.json --ref B
```

Setup: tiny Qwen3-MoE (4 layers, hidden 512, 64 routed experts, top-4, 108M params) built once
from a fixed seed and saved as an HF checkpoint; every mode loads it through `engine.from_hf`
(so the HF load mapping is exercised for every layout). Each rank gets its own seeded random
token sequence (2048 tokens) per step → global batch of 8 sequences, identical across modes.
bf16 params / bf16 reduce, fp32 master weights, AdamW lr 1e-4, grad-clip 1.0, all2all dispatcher,
no compile, no fp8.

| group | FSDPConfig | resulting layout |
|---|---|---|
| A baseline | `ep=1` | pure FSDP-8 |
| B legacy | `ep=8` | root `(fsdp=1, ep=8)`: dense replicated 8×, experts pure EP |
| C decoupled | `ep=8, decouple_ep_fsdp=True` | root `(1, efsdp=1, ep=8)`: dense FSDP-8 on `dp_shard`, experts pure EP |

## Result summary

- **Loss**: C matches B to `max rel diff 1.9e-05` over 50 steps; A vs B is `2.5e-05`. Step 0 is
  identical in the three groups. This is the bf16 reduction-order noise floor, not a systematic drift.
- **Per-parameter grad norms** (step 0, before any update): C vs B max rel diff `1.9e-03` on dense
  params and `1.6e-05` on expert params; A vs B: `1.5e-03` / `1.7e-05`. The expert side is expected
  to be near-identical: both paths reduce-scatter experts over `world/ep` and then `div_(ep)`
  (DESIGN §4.4). The dense-side difference is the replaced reduction
  (`RS over 1 + all-reduce over 8` → `RS over 8`).
- **Memory per rank** (tiny): dense parameter storage drops from 28.5 MiB (B) to
  3.6 MiB (C) = **1/8**, equal to the baseline A. Allocated memory after the first
  optimizer step 229.6 → 154.8 MiB, peak allocated
  439.7 → 365.8 MiB.
- **Medium model (3.4B, 8 layers, hidden 2048, 64 experts, seq 4096, 20 steps)**: loss C vs B `4.0e-04`
  (A vs B `7.0e-04`); dense params 836 → 105 MiB, peak allocated
  11861 → 8203 MiB; steady-state step time (steps 5–19)
  A 123 ms, B 170 ms, C 158 ms (-7.0% vs B). The tiny model is
  launch-overhead bound (two FSDP param groups per MoE layer) and is not used for timing claims.

## Acceptance (DESIGN §6-L1)

| criterion | result |
|---|---|
| B loss ≈ A within bf16 tolerance | max rel diff 2.5e-05 (tiny) / 7.0e-04 (medium) ✅ |
| C loss and per-layer grad norms ≈ A/B within tolerance | loss 1.9e-05 (tiny) / 4.0e-04 (medium); step-0 per-param grad norms ≤ 1.9e-03 dense, 1.6e-05 expert ✅ |
| C dense param memory per rank ≈ 1/8 of B | 28.5 → 3.6 MiB (tiny), 836.1 → 104.5 MiB (medium) ✅ |
| C step time ≤ B | medium: 158 vs 170 ms ✅ |
