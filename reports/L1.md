# L1 — single node, 8×H200: numerical equivalence of the decoupled layout

Command (PR-1 state of the branch):

```bash
PYTHONPATH=. torchrun --nproc-per-node 8 tests/model/run_decoupled_ep_fsdp_numerics.py \
    --modes A:ep=1 B:ep=8 C:ep=8,decouple=1 --steps 50 --seq-len 2048 --out l1.json
python tests/model/summarize_decoupled_ep_fsdp_numerics.py l1.json --ref B
```

Setup: tiny Qwen3-MoE (4 layers, hidden 512, 64 routed experts, top-4, 108M params) built once
from a fixed seed and saved as an HF checkpoint; every mode loads it through `engine.from_hf`
(so the HF load mapping is exercised for every layout). Each rank gets its own seeded random
token sequence (2048 tokens) per step → global batch of 8 sequences, identical across modes.
bf16 params / bf16 reduce, fp32 master weights, AdamW lr 1e-4, grad-clip 1.0, all2all dispatcher,
no compile, no fp8.

| group | FSDPConfig | resulting layout |
|---|---|---|
| A baseline | `ep=1` | pure FSDP-8 |
| B legacy | `ep=8` | root `(fsdp=1, ep=8)`: dense replicated 8×, experts pure EP |
| C decoupled | `ep=8, decouple_ep_fsdp=True` | root `(1, efsdp=1, ep=8)`: dense FSDP-8 on `dp_shard`, experts pure EP |

## Result summary

- **Loss**: C matches B to `max rel diff 5.0e-5` over 50 steps; A vs B is `3.6e-5`. Step 0 is
  identical to all printed digits in the three groups. This is the bf16 reduction-order noise
  floor, not a systematic drift.
- **Total grad norm**: C vs B ≤ `4.2e-3` (A vs B ≤ `3.0e-3`), same order.
- **Per-parameter grad norms** (step 0, before any update): C vs B max rel diff `7.7e-4` on dense
  params and `1.6e-5` on expert params; A vs B: `9.0e-4` / `1.9e-5`. The expert side is expected
  to be near-identical: both paths reduce-scatter experts over `world/ep` and then `div_(ep)`
  (DESIGN §4.4), and the numbers confirm it. The dense-side difference is the replaced reduction
  (`RS over 1 + all-reduce over 8` → `RS over 8`).
- **Memory per rank**: dense parameter storage drops from 28.5 MiB (B) to 3.6 MiB (C) = **1/8**,
  equal to the baseline A. Allocated memory after the first optimizer step drops 229.6 → 154.8 MiB
  (−33%; master weights + AdamW states of the dense params are no longer replicated), peak
  allocated 463.8 → 370.9 MiB (−20%).
- **Step time**: on the tiny model C is 5% slower than B (87.3 vs 82.7 ms) because every MoE layer
  now has two FSDP param groups (experts + rest) and their CPU-side launch overhead dominates a
  ~80 ms step. On the 3.4B "medium" model below — where communication volume matters — C is
  **4.7% faster** than B (189.8 vs 199.1 ms): the fp32 coalesced all-reduce of all dense grads over
  EP is gone, replaced by a bf16 reduce-scatter, and the dense all-gathers are 1/8 the size.

## Acceptance (DESIGN §6-L1)

| criterion | result |
|---|---|
| B loss ≈ A within bf16 tolerance | max rel diff 3.6e-5 (tiny) / 2.3e-4 (medium) ✅ |
| C loss and per-layer grad norms ≈ A/B within tolerance | loss 5.0e-5 (tiny) / 1.1e-4 (medium); step-0 per-param grad norms ≤ 7.7e-4 dense, 1.6e-5 expert ✅ |
| C dense param memory per rank ≈ 1/8 of B | 28.5 → 3.6 MiB (tiny), 836.1 → 104.5 MiB (medium) ✅ |
| C step time ≤ B | medium: 189.8 vs 199.1 ms ✅ (tiny: 87.3 vs 82.7 ms, launch-overhead bound) |
